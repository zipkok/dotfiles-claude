# 작업 스타일 (출력 형식)

행동 규칙(작업 단위·확인 요청 기준 등)은 `~/.claude/rules/work-behavior.md` 참조. 이 파일은 출력 형식만 다룬다.

## 언제 이 스타일을 쓰나

- **프로그레스바 + 테이블**: 여러 단계로 구성된 작업 (파일 다수 수정, 멀티 에이전트 위임, 마이그레이션 등)
- **액션 아이템**: 실행 계획을 승인받거나 작업 목록을 스캔하기 쉽게 정리해야 할 때
- **생략**: 짧은 Q&A, 탐색·설계 논의, 1~2단계뿐인 작업(단일 파일 typo 수정 등)에는 이 형식을 강제하지 않는다 — 일반 산문으로 답한다

## 액션 아이템 (체크리스트)

여러 파일·작업 항목을 스캔 가능하게 나열할 때 사용. 카테고리별로 묶고 체크박스로 완료 여부를 표시한다.

```md
**카테고리명**
- [ ] `파일 경로` — 무엇을 바꾸는지 한 줄
- [ ] `파일 경로` — 한 줄
```

완료 후에는 `[ ]` → `[x]`로 갱신해 다시 보여준다.

## 진행 상황 표시 (프로그레스바 + 테이블 + 이모지)

- **시점**: 작업 시작 전 전체 계획, 단계 완료마다 갱신(TaskUpdate 연동), 작업 완료 후 최종 요약
- **위치**: 응답 **최하단**에 배치한다 — 설명·분석·질문 등 본문을 먼저 쓰고, 프로그레스바+테이블은 응답의 마지막에 온다
- **내용**: 단계명, 설명, 작업 에이전트, 코드 diff

## 예시 (실제 채워진 모습)

> "인증 미들웨어에 JWT 검증 추가해줘" 같은 3단계 작업 — 본문(설명)이 먼저, 프로그레스바는 맨 아래:

기존 인증 미들웨어를 살펴보니 토큰 유무만 확인하고 있어 JWT 서명 검증이 빠져 있었습니다. `verifyJwt`를 추가해 서명이 유효하지 않으면 401을 던지도록 고쳤습니다.

### 📁 변경 파일

| 파일 | 변경 |
|------|------|
| `src/middleware/auth.ts` | JWT 검증 로직 추가 |

### 📝 diff 요약

```diff
- if (!token) return next()
+ if (!token) throw new UnauthorizedError()
+ const payload = verifyJwt(token)
```

| ⬜ | 테스트 | 유효/만료 토큰 케이스 테스트 작성 | 👤 Main |
