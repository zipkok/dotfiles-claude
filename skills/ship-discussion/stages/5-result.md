# Ship-Discussion · Result 단계 (참조 문서)

`SKILL.md`가 3~5단계에서 `workflows/ship-discussion-panel.js`(`stage: 'pipeline'`)를 호출할 때 그
안에서 수행되는 Result 부분의 상세 정의. **라운드 반복은 워크플로 내부에서 자동으로 이뤄진다** —
모든 쟁점이 해결되거나 최대 5라운드에 도달할 때까지, 사용자에게 "계속할까요?"를 묻지 않고 이어서
돈다 (Plan~Result 구간 전체가 사람 개입 없는 구간이기 때문). 결과가 돌아온 뒤 최종 리뷰만 사용자가
한다. (디버깅 목적으로 `stage: 'result'`로 한 라운드만 개별 호출하는 것도 가능)

**역할**: plan.md의 대안을 실제 쟁점별로 논쟁해 최종 결정 도출
**실행**: 쟁점마다 `agents/ship-discussion-position.md`를 입장 A/B로 2회 병렬 실행(plan.md의 대안
A/B를 그대로 옹호) → `agents/ship-discussion-synthesizer.md`가 `devils-advocate`로 라운드 판정

## 고민 과정 vs 결론 — result.md엔 결론만 남긴다

라운드별 입장 A/B 논쟁은 결정에 도달하기 위한 **과정**이지 산출물이 아니다. 문서 작성 원칙: "고민
과정은 메모로, 문서에는 정리된 팩트와 결론만" — 라운드가 3번이 걸렸든 1번에 끝났든, `result.md`엔
쟁점별 **최종** 대안 비교와 결정만 남긴다. 라운드 중간 상태는 워크플로 실행 중 메모리에만 있고
파일에 매 라운드 append하지 않는다 (마지막 라운드에서 해당 쟁점 항목을 덮어쓴다).

**"고민한 내용" 섹션은 이 원칙을 뒤집지 않는다** — result.md의 6단 구조(배경/현재/문제점/고민한
내용/결정/참고·주의사항) 중 "고민한 내용"은 대안 A/B의 **정리된 비교**(장단점, 왜 한쪽이 나은지의
근거)를 담는 것이지, 라운드별 논쟁 전문을 다시 붙이는 게 아니다. "과정(라운드 로그)"과 "대안 비교
정리(결론)"는 다른 것이다.

## 할 일 (워크플로 내부에서, 라운드마다 자동 반복)

1. 미해결 쟁점 목록(+ 이전 라운드에서 나온 입장 요지 + plan의 대안 A/B — 다음 라운드 position
   에이전트에게 컨텍스트로 넘길 것)을 다음 라운드에 넘긴다
2. 쟁점마다 position A/B가 plan의 대안을 각자 최강 논리로 옹호 (이전 라운드에서 받은 반론이
   있으면 대응)
3. synthesizer가 A/B를 devils-advocate로 검토해 `resolved: true/false` + 근거 판정
4. 모든 쟁점이 resolved거나 최대 5라운드에 도달할 때까지 1~3을 반복 — 사용자 확인 없이 자동으로
   돈다. 워크플로가 반환하는 `resolved`/`unresolved` 목록이 최종 상태다

## 최종 리뷰 (사용자 개입, 워크플로 반환 후 Main이 수행)

- 워크플로가 반환한 `resolved`/`unresolved`를 종합해 6단 구조(배경/현재/문제점/고민한 내용/결정/
  참고·주의사항)를 `output_dir/5-result.md`에 작성한다 (에이전트 결과를 있는 그대로 반영 — Main이
  임의로 바꾸지 않는다). 배경/현재/문제점은 spec.md·clarify.md 내용을 요약해 채운다. `unresolved`로
  남은 쟁점은 "고민한 내용"에 "결론: 미해결 — 최대 라운드 도달"로 남긴다
- 사용자에게 보여주고 승인 요청
- 불만족 시 사용자 명령에 따라 `stage: "result"`(라운드 추가) 또는 `stage: "pipeline"`(Plan부터
  재작업)으로 다시 호출

## 출력

```md
## 배경 (goal/scope)
{spec의 원 문제 제기 + 범위}

## 현재
{spec/clarify에서 확인된 현재 상황}

## 문제점
{현재 상황이 왜 문제인가}

## 고민한 내용 (대안 비교분석)
### {쟁점명}
- 비교한 대안: {A} vs {B}
- 각 대안의 장단점: {정리된 비교 — 라운드별 변화 과정 생략}
- (미해결/aporia인 경우) 결론: 미해결 — {사유}

## 결정 (제안)
{종합 결론 — 에이전트 판정 그대로}

## 참고/주의사항
- 가정: {...}
- 재검토 조건: {...}
- 잔여 리스크: {필요시만}
- 미해결 쟁점: {목록 또는 "없음"}
- 사인오프: {승인자/상태}
```

## 게이트 조건

- 모든 쟁점이 resolved거나, 미해결로 남은 쟁점의 사유가 명시돼야 한다
- "결정"이 검토 내용에 근거해야 한다 (Main이 새로 지어내지 않는다)
- **"고민한 내용"은 대안 비교의 정리된 결론만** — 라운드별 논쟁 전문이 result.md에 남으면 안 된다
- 사용자 최종 승인 전에는 스스로 세션을 끝내지 않는다 (자가 게이트 점검으로만 규율 유지 — Stop 훅은
  "응답 대기 중"과 "진짜 종료"를 구분 못 해 오히려 위험하므로 쓰지 않는다)
