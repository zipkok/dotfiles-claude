# Ship-Discussion · Plan 단계 (참조 문서)

`SKILL.md`가 3~5단계에서 `workflows/ship-discussion-panel.js`(`stage: 'pipeline'`)를 호출할 때 그
안에서 수행되는 Plan 부분의 상세 정의. Main이 혼자 처리하지 않고 여러 에이전트가 협의한다. (디버깅
목적으로 `stage: 'plan'`만 개별 호출하는 것도 가능 — `workflows/ship-discussion-panel.js` 참조)

- **역할**: 쟁점을 진행 순서·질문 트리로 설계
- **실행**: `mece` / `first-principles` / `pre-mortem` / `inversion` 4개 기법을 각각 적용하는
- `agents/ship-discussion-technique-agent.md` 4회 병렬 실행 → `agents/ship-discussion-synthesizer.md`가
devils-advocate로 검토해 하나의 계획으로 수렴

## 할 일 (워크플로 안에서 에이전트들이 수행)

1. 4개 기법-에이전트가 spec+clarify의 쟁점 목록을 각자의 렌즈로 독립 분석
   - mece: 분류 겹침·누락 점검
   - first-principles: 암묵적 가정 재검토
   - pre-mortem: 이 진행 순서대로 하면 나중에 뭐가 문제될지
   - inversion: "어떻게 이 계획을 망칠까"를 뒤집어 보강점 도출
2. synthesizer가 4개 결과의 동의/충돌 지점을 정리하고, 충돌은 근거로 판단해 최종 진행 순서·하위
   질문 목록으로 수렴
3. **대안 도출**: 진행 순서가 정해진 쟁점(특히 하위 질문이 "이걸 할까 저걸 할까"류인 것) 중 실제
   결정이 필요한 것마다 **비교 가능한 대안을 2개 이상** 뽑는다. 이 대안이 Result 단계에서 position
   A/B가 실제로 논쟁할 대상이 된다 (position이 임의 입장이 아니라 여기서 정의한 구체 대안이 됨)
4. **평가기준·가중치 설계**: 그 대안들을 무엇으로, 얼마나 중요하게 비교할지 정한다 — 기준마다
   가중치(합 100%)와 채점 방법(데이터 vs 판단)을 명시. 이 기준이 Review 단계의 정량 채점에 쓰인다

## 출력

쟁점 분류(MECE)와 진행 순서를 별도 섹션으로 나누면 같은 정보(독립/의존 여부)를 두 번 다른 포맷으로
반복하게 된다 — 분류를 진행 순서 목록의 각 항목 안에 표기해 한 번만 쓴다.

```md
## 쟁점별 진행 계획
### 1. {쟁점명} (독립 | 의존 — 선행: {쟁점명})
- 하위 질문 1: {질문}
- 하위 질문 2: {질문}

### 2. {쟁점명} (독립 | 의존 — 선행: {쟁점명})
...

(독립 쟁점 먼저, 의존 쟁점은 선행 쟁점 뒤에 배치. 쟁점당 하위 질문 1~3개)

## 대안 (쟁점별, ≥2개)
### {쟁점명}
- 대안 A: {요약 1~2줄}
- 대안 B: {요약 1~2줄}
(결정이 필요한 쟁점마다. 단순 사실확인 쟁점처럼 "대안"이 성립하지 않으면 생략 가능 — 그 경우 이유를
한 줄로 남긴다)

## 평가기준 + 가중치 (합 100%)
| 기준 | 가중치 | 채점 방법 |
|------|--------|-----------|
| {예: 실행 난이도} | {예: 30%} | {데이터 기반 | 정성 판단} |

## 기법별 발견 요약
- mece: {분류 겹침·누락 점검 결과}
- first-principles: {암묵적 가정 재검토 결과}
- pre-mortem: {진행 순서상 예상 실패 지점}
- inversion: {"어떻게 망칠까"에서 도출한 보강점}

## 기법 간 충돌·조정
{두 개 이상의 기법이 서로 다른 조치를 제안한 지점 + synthesizer가 devils-advocate로 어떻게
조정했는지. 충돌이 없었으면 "충돌 없음"만 기재}

## {N}라운드 — 사유 (재작업 시에만 추가, 최초 작성 시 이 섹션 생략)
{이전 Review fail이 지적한 보강 지점 + 이번 라운드에서 각각 어떻게 반영했는지}
```

## 게이트 조건

- 4개 기법 결과가 모두 반영됐는지 (한쪽만 채택하고 나머지를 무시하지 않았는지)
- 진행 순서·하위 질문이 모든 쟁점에 존재하는지
- 결정이 필요한 쟁점마다 대안이 2개 이상 있는지 (없으면 생략 이유가 명시됐는지)
- 평가기준의 가중치 합이 100%인지
- 재작업 라운드라면 이전 Review fail의 보강 지점이 이번 계획에 실제로 반영됐는지
