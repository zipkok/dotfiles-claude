# Ship-Discussion Run · Clarify (socratic-method)

spec.md의 Self-Review 결과 중 **red-flag 탐지 목록** + `[NEEDS CLARIFICATION]` 목록 + 여기서 새로
찾은 **모호어**("개선","빠르게","충분히" 등)에 있는 쟁점부터 우선 다룬다. 목록에 없는 쟁점은 시간이
남으면 다룬다. 유형1 질문은 한 번에 하나씩 순차로 던진다(배치하지 않음 — 이유는 `stages/
2-clarify.md` 참조).

## 쟁점별 명확화

### {쟁점 1} — 유형: {유형1 | 유형2} {(red-flag 목록에 있었으면 표시)}

(유형1인 경우)
- 주장(spec 원문): {쟁점 문구}
- 명료화 질문: {"이게 정확히 무슨 뜻인가요?" 류}
- 사용자 정의: {답변}
- 함의: {그 정의에서 논리적으로 따라 나오는 결과}
- 반례 (있었다면): {충돌 지점}
- 결과: {재정의: 새 정의} 또는 {aporia: 불확실함이 드러난 지점}

(유형2인 경우)
- Main 판단: {함의 추적 + 다른 쟁점·전제와의 충돌 검토}
- 결론: {일관됨 | 재정의 필요(초안 포함) | 모순 발견}
- 사용자 승인: {승인 | 에스컬레이션(spec 전제 문제로 1단계 재진행)}

(이미 명확해 스킵하는 경우)
- 스킵 사유: {한 줄 근거 — 왜 이미 명확한지}

### {쟁점 2}
...

(spec.md의 모든 쟁점을 훑되, 이미 명확한 쟁점은 "스킵 사유" 한 줄만 남기고 스킵 가능. 단, 모든
쟁점이 유형2 또는 스킵이면 안 됨 — 최소 1개는 유형1 절차를 실제로 끝까지 거쳐야 함. aporia로 끝나도
유효한 결과)

## Clarify 게이트 자가 점검
- [ ] 최소 1개 쟁점이 유형1로 분류돼 명료화 질문 → 함의 도출 → 재정의/aporia까지 실제로 거쳤는가
